# Kanban command and event boundary

`npm run kanban:contract:generate` regenerates the checked Rust serde fixture at `src/kanban/boundaryContract.generated.ts`. `npm run test` and `npm run build` fail if the fixture differs. The generator tracks the full field signatures of prioritized Rust structs (including newly added fields), selected wire projections, workflow lifecycle variants, and prioritized command signatures. TypeScript structural checks cover revisions, nullable environment/operation fields, snapshots/deltas, cleanup and Pi intent. The older UI types permit some missing optional fixture fields; **real Rust responses serialize those as explicit null**. Do not interpret `invoke<T>` as runtime validation. This is a drift check, not a deserializer or an app-wide DTO generator. Extend its mapping and checked projections when adding wire fields used by the UI. Rust `String` lifecycle phase and error-code fields are currently unconstrained by Rust enums; their frontend literal unions are UI policies, not exhaustively checked backend enums.

The board controller is the single owner of the `kanban-board-changed` Tauri subscription. Broadcast deltas advance board completeness only in contiguous revision order; command responses merge affected records without claiming completeness. Gaps trigger the existing snapshot recovery. The controller publishes canonical cards **before** typed detail invalidations (`cardId`, `boardRevision`, `recordRevision`); duplicate/older records do not trigger detail reads. A missing event is recoverable by a board snapshot; command responses supply independent affected-entity outcomes. The detail coordinator coalesces invalidations, rejects superseded and cross-selection responses, and retries an obsolete read once per newer canonical record. A stale read is not an IPC error; genuine read failures remain retryable. Closing or unmounting cancels projection, not the underlying IPC.

Tauri events (Kanban, Pi, releases, credentials) are notifications, not a durable queue. Consumers must subscribe/unsubscribe within their existing owner lifecycle; never infer completeness from an event or assume it precedes a command response. Pi's `eventBroker` retains its current centralized subscription. Release and credential listeners retain their current lifecycles; this card does not migrate their delivery policy. Operations needing an independently observable result must use their command response or re-read authoritative state; polling/snapshot gap recovery remains available when broadcasts are lost. The Rust cleanup preflight reports blockers and error descriptions as strings, not a stable typed error-code enum yet.
